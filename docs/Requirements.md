## 1. 项目概述

使用 **Go 语言**从零实现一个基于 Git 原理的简易版本控制系统（命名：**GoGit**），不依赖 `go-git` 等现成 VCS 库，核心数据结构（对象模型、暂存区、引用、合并）全部手写。系统以 **REST API + Web 管理页面** 的形式交付，用户通过浏览器完成仓库管理与版本操作。

## 2. 技术栈约束

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Go（标准库为主） | 哈希用 `crypto/sha1` + `crypto/sha256`，压缩用 `compress/zlib`，禁止引入现成 VCS 库 |
| 前端 | Vue 3 / React + Tailwind CSS | 现代设计系统，满足"美学卓越"红线 |
| 交付 | Docker Compose 单容器 | 多阶段构建，支持 ARM64 + AMD64，`localhost` 可访问 |

## 3. 功能需求

### 3.1 核心对象管理（Object Store）

- **Blob 对象**：存储文件原始内容，对象格式 `blob <size>\0<content>`。
- **Tree 对象**：存储目录结构，条目包含 模式(mode) / 文件名 / 子对象哈希，指向 Blob 或子 Tree。
- **Commit 对象**：存储提交信息，包含 根 Tree 哈希、父提交哈希（支持多个，用于 merge）、作者、提交信息、时间戳（GMT+8）。
- **哈希算法**：支持 **SHA-1 与 SHA-256 双算法**，仓库初始化时可配置，默认 SHA-1（与 Git 对象格式兼容）。
- **存储布局**：`.gogit/objects/<前2位哈希>/<剩余哈希>` 扇出存储。

### 3.2 暂存区与提交（Staging & Commit）

- **add**：将工作区文件写入暂存区（`.gogit/index` 文件），同时生成对应 Blob 对象入库。
- **commit**：由暂存区构建快照 Tree 树，生成 Commit 对象，并更新当前分支引用。
- **status**：展示工作区 / 暂存区 / HEAD 三者间的差异状态（已暂存、已修改未暂存、未跟踪）。

### 3.3 分支管理（Branch）

- **创建分支**：在 `.gogit/refs/heads/<name>` 写入当前提交哈希。
- **切换分支**：修改 `.gogit/HEAD` 指针，并将工作区文件恢复为目标分支快照。
- **合并（三方合并算法）**：
  - 自动查找合并基点（merge base，最近公共祖先）；
  - 对比 base → ours 与 base → theirs 的差异；
  - 无冲突变更自动合并并生成合并提交（双父 Commit）；
  - 冲突文件写入冲突标记（`<<<<<<< / ======= / >>>>>>>`）并明确报告。

### 3.4 存储压缩

- 所有对象文件写入磁盘前使用 **zlib** 压缩，读取时解压；压缩/解压逻辑封装在对象存储层，对上层透明。

### 3.5 Web 管理页面（前端）

单页管理界面，至少包含以下视图：

1. **仓库总览**：当前分支、HEAD 提交、对象数量统计、仓库路径。
2. **文件浏览器**：工作区文件树，支持单文件/目录 add 到暂存区。
3. **暂存区视图**：已暂存文件列表、变更状态标识。
4. **提交历史**：按分支展示提交列表（哈希、信息、时间、父提交），支持查看单次提交快照。
5. **分支管理**：分支列表、创建、切换、发起 merge、冲突结果展示。
6. **对象查看器**：按哈希 inspect Blob / Tree / Commit 的解析后内容。

### 3.6 后端 REST API

为前端全部功能提供 REST API（健康检查、仓库信息、文件树、add/commit/status、分支 CRUD、merge、对象查询）。接口文档独立维护于 `docs/API.md`，含请求/响应示例与错误码表。

## 4. 非功能需求

- **Docker 交付**：`docker compose up` 一条命令启动，Web 服务通过 `localhost` 访问；镜像支持 ARM64 + AMD64。
- **美学卓越**：UI 使用 Tailwind 等现代设计系统，间距、排版、交互反馈达标，拒绝"工程师界面"。
- **时区**：提交时间与前端时间展示统一使用 **GMT+8**。
- **日志**：后端使用统一 Logger（含 level 控制），禁止散落 `fmt.Println` 调试输出。
- **测试**：核心引擎（对象读写、index、三方合并）须有 Go 单元测试；交付含 API Smoke 测试。
- **健壮性**：所有外部输入（API 请求体、磁盘对象反序列化）必须做结构完整性校验。

## 5. 验收基线（可测量）

| # | 验收项 | 基线 |
|---|---|---|
| 1 | 对象格式正确性 | SHA-1 模式下，同一文件生成的 Blob 哈希与 `git hash-object` 输出一致 |
| 2 | 压缩有效性 | 磁盘对象文件为 zlib 压缩格式，解压后内容与原始对象字节一致 |
| 3 | 往返一致性 | add → commit → 切换分支 → 切回，工作区文件字节级还原 |
| 4 | 三方合并 | 无冲突场景自动合并成功；冲突场景产出带冲突标记的文件且 API 返回冲突清单 |
| 5 | 双算法 | SHA-1 / SHA-256 两种模式初始化的仓库均可完成全功能闭环 |
| 6 | 一键启动 | 干净环境 `docker compose up` 后 Web UI 可访问且核心流程可用 |
| 7 | 测试 | `go test ./...` 通过；API Smoke 测试在容器内通过 |

## 6. 范围边界（Out of Scope）

- 多用户 / 权限认证（定位为单机本地工具，免登录）。
- 远程仓库（clone / push / pull）。
- 标签（Tag）、rebase、stash 等高级 Git 功能。
- 大文件（LFS）支持。

## 7. 歧义与决策记录

| # | 原始表述 | 决策 |
|---|---|---|
| 1 | "SHA-1/SHA-256 **压制**哈希键" | 判定为"生成"之笔误；实现为双算法可选，默认 SHA-1 |
| 2 | "基础的 merge" | 界定为文件级三方合并 + 文本行级合并，冲突写标记；二进制文件冲突一律人工处理 |
| 3 | "前端管理页面" | 界定为单页管理 UI，免登录；CLI 不作为交付要求（API 为唯一操作入口） |
